# Method order and execution branches

Folder numbers express the manuscript's methodological sequence, not a single dependency-free batch run. Keep mouse, clinical and pan-cancer data branches separate.

| Order | Folder | Key calculations / sequence |
|---|---|---|
| 01 | `01_reference_annotation` | `step4b` inferCNV → `step4c` CNV verdict → `step10` clinical reference/deconvolution annotation. Existing reference and deconvolution outputs are inputs. |
| 01b | `01_spatial_cnv_regions` | `step00` raw CAR/total UMI → `step01` spot master → existing folder-02 `step02` CAR calling → `step03` spatial CNV/tumour zones. Supplies `spot_regions.csv`; marker/region-definition differences are documented. |
| 02 | `02_scissor` | CAR calling (`step02`); pooled ComBat/Scissor (`step52`) and alpha evaluation (`step57`, `step91`); sparse-label assembly (`step53b`); forward/reverse ROC (`step21`, `step22`). Restored `step06` exports legacy cohort coefficients and curated `step07` exports the integrated spot table. `scissor_meta_preprocess.R` is an author-session metadata helper, requiring `dataset` and `GEOID`. |
| 03 | `03_functional_states` | `step54a` gene-set export → `step54_gsva_grpr_v2.py` expression/panel preparation → `step54b` GSVA scores; `step58` feature expression/classifier → `step78a` C7 export → `step78` LASSO/state panels → `step78b` GSVA → `step82` within-section z scores and labels. `step93`, `step93b`, `step94` retain distinct ROC targets/scopes. Do not substitute their labels for one another. `legacy_dependencies/step04 → step17 → step18 → step48` reconstructs the separate def5 input read by `common.grpr_labels()`; these are not current M5-quadrant labels. |
| 04 | `04_fourier` | `step96` band reconstruction, toroidal-shift correlations and BH correction. Functional labels and annotated spot fields must already exist. |
| 05 | `05_mib_definitions` | `step60` mouse-aligned clinical MIB; `step102` deconvolution-defined perivascular MIB; `step62` mouse ring features; restored `step32` supplies the separate ring-niche input for `step61`; `step103` definition agreement. `run_cibersort_stnr.R` requires the external CIBERSORT implementation/signature. `step105b` retains clinical pseudobulk component scoring/ranking only and runs after folder 09 prepares that input. |
| 06 | `06_spatial_neighbourhood` | Mouse `step61` mixed-model feature families; added `step09` CAR-positive proportion tables; `step01_region_define_stats` → `step04` regional GR/PR tables → `step07` separate TAM/CAF neighbourhoods → `step09` simultaneous neighbourhoods → `step12_perivascular_enrichment` section-specific fold enrichment. `step01_nr1_panelI_knn` is the separate pooled-section/stratified-permutation neighbour analysis. Clinical `step13` prepares `ccr1_spots_all.csv` → `step114` final per-section 1,000-permutation analysis. `step102_myeloid_caf_coloc_fig` retains correlation/OR statistics and CSV output only; despite its original filename, it no longer draws figures. |
| 07 | `07_functional_correlations_gsea` | `step01_prep_data` and `step05` functional/marker correlations; `step76_blocks` supplies marker definitions. `step01_nr1r1_rank` → `step02_tcell_gsea.R` functional GSEA. Gene-set selection/result tables remain because they document the analysis; rendering is excluded. |
| 08 | `08_imaging_conversion` | `batch_mics_to_h5ad.py` converts imaging tables. Imaging proximity/statistical analysis entry points were not present in the archive. |
| 09 | `09_clinical_pseudobulk_gsea` | `step100` perivascular MIB pseudobulk → `step101c` limma-voom DE → `step101b` GO/KEGG/Hallmark enrichment. `step105a` separately prepares deconvolution-defined MIB pseudobulk for folder 05 component scoring. |
| 10 | `10_survival` | `step83a` patient-level exposure export → `step83b` clinical Cox/log-rank tables. `survival_km_cox.R` and `survival_tests_generic.R` are separate cohort/table entry points. `step02_pancancer_survival.R` retains pan-cancer age/gender-adjusted Cox and cutoff calculations; later stage/race fallback plotting versions are excluded. |

Original script headers and input/output paths document the expected filenames. `PROJECT_ROOT` refers to the original analysis-data tree, not this repository. Use the configured runner to make modules in other release folders importable.
